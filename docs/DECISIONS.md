## Decisions made while building

| ID  | Topic                                   | Decision and reason                                                                                                                                                                                                                                                                                                                                                                                                                |
| --- | --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| D18 | Club directory                          | The team supplied a real club list; it replaces the eight sample clubs of Appendix A as seed data (`apps/api/src/db/seeding/clubsData.js`). The product name stays the neutral "Campus Clubs Portal" (spec rule 7). Categories were mapped onto the existing category list.                                                                                                                                                        |
| D19 | Sample club                             | The sample Leader, Vice Leader, Secretary, Event Coordinator, Media Lead and Member accounts live in **Hut Labs** (the robotics club), standing in for the spec's "Robotics Club".                                                                                                                                                                                                                                                 |
| D20 | Case-insensitive uniqueness             | In addition to storing lower-case values, `CHECK (email = lower(email))` and the same for `username` enforce it in the database, so TC-DB-03 holds even for raw inserts.                                                                                                                                                                                                                                                           |
| D21 | Timestamps                              | Stored as UTC ISO-8601 text (`string(30)`) on both databases, not native timestamp columns. Guarantees identical round trips (TC-DB-13) and lexical ordering.                                                                                                                                                                                                                                                                      |
| D22 | Logout                                  | `POST /auth/logout` works from the refresh cookie alone (not `auth`), so an expired access token cannot keep a session alive. Always returns 200.                                                                                                                                                                                                                                                                                  |
| D23 | Change password                         | The refresh cookie is scoped to `/api/v1/auth`, so `/me/change-password` cannot see the current session family. It revokes **all** sessions and returns a fresh access token and refresh cookie for the caller.                                                                                                                                                                                                                    |
| D24 | Forced password change                  | While `must_change_password` is set, only `POST /me/change-password` works (even `/me` returns 403 `PASSWORD_CHANGE_REQUIRED`). The login response carries the flag so the web app can redirect.                                                                                                                                                                                                                                   |
| D25 | Brute-force limiter                     | In-memory per account+IP store (5 failures / 15 min). Correct for one API instance; move to the database or Redis before running several instances.                                                                                                                                                                                                                                                                                |
| D26 | Styling                                 | Plain CSS files built on the design tokens instead of CSS modules, to keep Phase 0 small. Components never contain raw colours. Can be migrated to CSS modules later.                                                                                                                                                                                                                                                              |
| D27 | Component tests                         | `fetch` is stubbed with a small helper instead of MSW in Phase 0. MSW can replace it when screens multiply.                                                                                                                                                                                                                                                                                                                        |
| D28 | Husky                                   | Not installed yet (the folder is not a git repository on the author's machine until now). Add `husky` with a pre-commit running `npm run lint` before the team pushes.                                                                                                                                                                                                                                                             |
| D29 | Bcrypt cost in tests                    | `BCRYPT_COST` env var (default 12, tests use 4) so the suite stays fast. Production must keep 12 or higher.                                                                                                                                                                                                                                                                                                                        |
| D30 | Club ids in the web app                 | Workspace routes use the club's UUID (`/club/:clubId`); the API accepts either id or slug for club paths.                                                                                                                                                                                                                                                                                                                          |
| D31 | Single API instance                     | The notification stream hub (SSE), the login limiter, the posting limiter and the chat limiter are in memory. Run one API instance or move them to Redis or the database before scaling out.                                                                                                                                                                                                                                       |
| D32 | Three start-screen logins               | Student, Club Member and Administrator are three entry points to the same account system (D3). Each login only admits the right kind of account; roles are still enforced by the server. A club member who uses the Student login lands on the student side.                                                                                                                                                                       |
| D33 | Chatbot retrieval                       | Keyword scoring in JavaScript over public portal rows and `docs/faq/*.md`, instead of SQLite FTS5 or PostgreSQL full text, so it behaves the same on both databases. Official `@anthropic-ai/sdk` on the server, model from `LLM_MODEL` (default `claude-opus-5-5`), server-side fallback enabled, low effort. Works without a key in extractive mode.                                                                             |
| D34 | Purpose-bound tokens                    | Stream and calendar-feed tokens carry a `purpose` claim and are rejected as access tokens.                                                                                                                                                                                                                                                                                                                                         |
| D35 | Waitlist is per form                    | The waitlist is switched on when registration is published (`forms.waitlist_enabled`); otherwise a full event returns SEATS_FULL as in TC-REG-05.                                                                                                                                                                                                                                                                                  |
| D36 | Hold counting                           | Every tentative hold, including one on an approved event, counts toward `MAX_ACTIVE_HOLDS_PER_CLUB` until the final hall request converts it. The end-to-end stack relaxes the limit.                                                                                                                                                                                                                                              |
| D37 | Dark theme text colour                  | `--brand-text` is the red used for text and links: the brand red in light, `#ff8e9c` in dark, because `#c72c43` is only 3.5:1 on the dark background.                                                                                                                                                                                                                                                                              |
| D38 | Mail capture                            | `MAIL_OUTBOX_FILE` writes outgoing mail to a file for end-to-end tests; the API refuses it in production.                                                                                                                                                                                                                                                                                                                          |
| D39 | Object storage                          | Local disk only for now; the `s3` driver is not implemented (see Known gaps).                                                                                                                                                                                                                                                                                                                                                      |
| D40 | Supplied Amrita UI replaces the web app | The team's `genesis-campus-connect` frontend (Student, Club Authority, OSA and Events Section) replaces the earlier `apps/web`. Its design and pages are kept as delivered. Its workflow (club request, online review, hard-copy check, OSA approval, publish) differs from the earlier OSI and hall-booking flow, so it is implemented as a new `gov` module. The earlier modules stay in the API, tested, but unused by this UI. |
| D41 | Same engine in browser and server       | The pure workflow engine (`packages/shared/src/gov`) runs in the browser for an instant answer and again on the server, which is the authority. The server's state replaces the local copy; a refused change is dropped and reported. Every screen stays unchanged while the rules are enforced server-side.                                                                                                                       |
| D42 | Storage of the governance state         | One JSON row per entity in `gov_docs(collection, id, ord, data)` plus counters and the demo clock in `gov_meta`, so the same migration runs on SQLite and PostgreSQL. Each action loads the state, runs the engine and writes only changed rows in one transaction; PostgreSQL locks the meta row first.                                                                                                                           |
| D43 | Fixed demo date                         | The seeded events, deadlines and the 2-day notice rule are built around 10 October 2026, so the engine clock and `TODAY` stay fixed there (as in the supplied UI). Replace `demoClock.js` and the seed before real use.                                                                                                                                                                                                            |
| D44 | Demo accounts                           | STU2026001, CLUB001, CLUB002, OSA001 and EVT001 are seeded only when `SEED_DEMO_PORTAL=true` and never in production. Their passwords are shown by the sign-in screen's Fill button, so they are public demo credentials by design.                                                                                                                                                                                                |
| D45 | One door per account                    | `POST /auth/login` accepts `portal`. A student account cannot enter the Administrator screen, a Club Authority account is not also a student, and the wrong door gets the same message and counts as a failed attempt, like a wrong password.                                                                                                                                                                                      |
| D46 | What each portal receives               | The state is filtered on the server: students get published events only; a club gets its own requests and promotions in full and other clubs' pending requests as a time slot (so venue clashes still show); administrators get everything.                                                                                                                                                                                        |
| D47 | Inputs the engine does not check        | Action arguments are bounded (string length, depth, list size). Posters must be real PNG, JPG or WebP files (signature check) and are stored under `/uploads`; unknown document keys are dropped. The duplicate-club check is recomputed on the server and the browser's result is ignored.                                                                                                                                        |
| D48 | Seats and registrations                 | Registrations live in `gov_registrations`; the seat check and insert run in one transaction under the state lock, so two students cannot take the last seat. The two seeded registrations of the demo student are subtracted from the sample counts so the numbers match the supplied UI.                                                                                                                                          |
| D49 | Assistant engine                        | The student Campus Assistant uses Claude when `ANTHROPIC_API_KEY` is set (published events, clubs and process notes are delimited as untrusted data) and the built-in rules otherwise. The UI labels the source honestly.                                                                                                                                                                                                          |
| D50 | Demo reset                              | `POST /gov/reset` (OSA only) restores the sample data and is refused unless the demo accounts are enabled. A student's reset only touches their own account.                                                                                                                                                                                                                                                                       |
